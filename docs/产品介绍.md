## 1. 产品定位与生态位

**miyako_life 是一条离线角色包产线**：galgame 解包原料 → `dist/{package_id}.char/`，
拷入桌宠 miyako-pet 的 `data/characters/` 即可运行。当前只做《9-nine-》EP1 的九條都
（第二游戏泛化推迟）。

在 miyako 生态中的位置：

```text
游戏《9-nine-》EP1 ──解包──▶ 原料区 ──miyako_life（本产品）──▶ miyako.char
                                                                    │
                                              拷入 miyako-pet data/characters/ + 一行 settings
                                                                    ▼
                                              桌宠运行：聊天 / 表情 / GPT-SoVITS 音色
```

产品形态是**给 pet 无工具运行时的静态角色扮演包**：人设卡（character_card.yaml）每轮
对话被 pet 的编排器拼进 system prompt，LLM 只负责说话——**行为一致性必须全部预先编码进字段**。
因此本产品的验收标准是**扮演辨认度**（盲测判定线），而非决策质量。

四个 CLI 入口构成完整生命周期：
`build`（DAG 全跑）→ `report`（人工决策页）→ `pack`（出厂打包）→ `accept`（深路径验收，待实装）。

## 2. 设计原则（不可协商的部分）

违反任何一条 = 返工。这些原则直接决定了模块的实现形态：

| # | 原则 | 一句话 | 实现落点 |
|---|---|---|---|
| L1 | 单一事实源 | voice_map.json 唯一上游，E1 产出后 sha256 冻结；失效传播经 hash 不经调用关系 | E1 + 各产物头部 hash |
| L2 | 模块隔离 | upstream/persona/voice/pack 四工序互不 import，只经 contracts 通信 | 约束 A + CI 执法 |
| L3 | 写权限显式化 | 每个产物的写入方在 write_scopes.yaml 声明；edge_voice 等只能 pack 代写 | write_scopes + 检查 |
| L4 | **统计归脚本、归纳归 LLM** | 一切频次/比例/概率由确定性脚本产出并过黄金值断言；LLM 只做带证据引用的归纳 | E3/E4 分工 + 逐字引用门 |
| L5 | 人工决策收敛单页 | 全部人工环节收敛到报告页；决策绑定产物 hash（Y5），产物变更即 stale | report_builder + decisions.yaml |
| L6 | 幂等与断点续跑 | 重跑产物 byte 级一致；LLM 按样本组缓存，原料不变零成本 | 缓存指纹 + 确定性落盘 |
| L7 | 契约不自造语义 | 情绪闭集 sync 自 pet；schema 与 pet 模板经 golden 样例双向互锁 | contracts + golden_pair |
| L8 | 资产禁区与外发面声明 | 游戏资产只进 work/（gitignore）；云端外发仅限抽样文本，音频零外发 | CI 执法 + BYOK |
| D16 | 灵魂优先 | card 是 pet 的灵魂、life 是灵魂加工厂；演进不受 pet 现行消费面封顶；密化优于截断；schema bump 前 pet 白名单先行 | E4 密化 + 预算收敛 |
| — | 宁空勿造 / 宁严勿松 | 验证过的空表是结论不是缺席；护栏宁可不发不可错发 | 词表空表史、出厂检查 |

**最高铁律（L4 展开版）**：统计归脚本、归纳归 LLM。三个典型落点——
①E3 的所有比例（口癖率、第一人称占比）由脚本计算并过黄金值断言，LLM 无权给数字；
②词表由 E3 打分 + 人工裁定产生，**E4 不得生成自己的输入过滤器**（自证隔离）；
③P3 语气示例由 LLM 挑选，但脚本逐字校验引用（见 §6.2）。

## 3. 系统架构总览

### 3.1 工序 DAG（11 序）

```text
e0_input_check ─┬─▶ e15_translate ─┬─▶ e1_semantic ─┬─▶ e3_dna_stats ─▶ e4_persona ─▶ e6_validate ─┐
                │                  │                │                                              ├─▶ report_builder ─┐
                └─▶ e2_sprites ────┼────────────────┼─▶ v1_audio_prep ─▶ v2_train_prep ────────────┤                    ├─▶ pack
                                   └────────────────┴──────────────────────────────────────────────┴────────────────────┘
```

依赖拓扑由 Kahn 算法在运行时计算（`build.topo_sort`），依赖缺失/成环直接 fail-fast。
每道工序是 `upstream/persona/voice/pack` 下的一个模块，统一签名
`run(raw_root, profile_path, work_dir) -> dict`，由 build 编排调用。

### 3.2 目录结构与隔离约束

```text
miyako_life/
├── build.py            # 总编排 DAG + 成本汇总
├── contracts/          # 🔑 三方唯一共享层（约束 A 唯一例外）
│   ├── emotion_defs.py       # 9 元情绪闭集（sync 自 pet server/emotion_defs.py）
│   ├── char_schema/          # manifest/character_card/relationship/tts_config 四 JSON Schema
│   ├── golden_pair/          # 与 pet 模板双向互锁的黄金样例
│   ├── write_scopes.yaml     # 三方写权限声明
│   ├── cost.py               # CostMeter（构造自动载账）
│   ├── llm.py                # GLM 客户端（coding 端点、429 指数退避）
│   ├── estimation.py         # pet 同口径 token 估算
│   ├── naming.py             # 跨工序命名单一来源
│   ├── logging_util.py       # 全链路日志
│   └── interface.yaml        # 产消对账正本（谁生产谁消费）
├── upstream/           # E0/E1/E1.5/E2（游戏文件 → 事实源）
├── persona/            # E3/E4/E6（台词 → 灵魂）
├── voice/              # V1/V2（语音 → 训练材料/参考池）
├── pack/               # report_builder/packager/factory_check（成品与闸门）
├── config/             # 游戏 profile（锁定决策档案）
├── tests/ci + local    # 两层测试（CI 187 / local 26）
└── work/ dist/ card/   # 车间/成品/镜像（全部 gitignore）
```

**约束 A（模块隔离）**：四工序目录之间禁止互相 import，也不得 import build.py；
共享只许 contracts；contracts 不得反向 import 工序。CI 测试 `test_import_isolation`
扫描全部 import 语句执法。**约束 B（资产禁区）**：png/jpg/ogg/wav 不进 git，
`test_no_game_assets_in_git` 用 `git ls-files` 扫描执法。

### 3.3 运行环境

复用宿主 conda 环境 `GPT-SoVITS`（python 3.10 + torch 2.5.1 cu124），不新建 venv；
`python -s`（PYTHONNOUSERSITE=1）密封模式，与训练/试听同一解释器世界。
所有 CLI 支持直跑（`python -s pack\packager.py …`）——各文件在模块头部做
`__package__` 自举，保证脚本模式下 contracts 可导入。

## 4. 契约层 contracts——三方共享的唯一通道

### 4.1 emotion_defs——9 元情绪闭集

`SENTIMENT_CLOSE_SET = {normal, happy, shy, pout, angry, sad, surprise, thinking, sleepy}`。
文件头注明 sync 来源（pet server/emotion_defs.py）。闭集是全产线的"情绪宪法"：
E2 验收立绘键集、E3 统计情绪桶、E4 抽样分组、E6 判定输出标签、出厂检查互锁——**闭集外即违规**。
`DEFAULT_EMOTION = normal` 是一切 fallback 链的终点。

### 4.2 char_schema——四份 JSON Schema + 双向互锁

manifest / character_card / relationship / tts_config 四份 Draft 2020-12 schema。
关键设计：`golden_pair/miyako_sample/` 里的同一份样例必须**同时**通过 life schema 与
pet 侧 `tools/new_character.py` 模板校验（双向互锁）——life 的"执法案"与 pet 的"运行时"
永远有公共参照物。CI 每次跑 `test_char_schema` 验证互锁。

### 4.3 write_scopes——写权限显式化

每个产物文件声明唯一写入方（persona/voice/pack 身份）+ pack 的 proxy_write
（如 edge_voice 由 pack 代写）+ override_rule。防止"谁都改一笔"的管线腐化。

### 4.4 cost.py——CostMeter（构造自动载账）

LLM 计量的唯一通道：`record(slot, model, tokens, cost, group)` → `save()` 落盘
`work/llm_cost.json`（无时间戳字段，重跑字节可复现——L6 纪律）。
**关键语义（2026-09-19 修复）**：构造函数即载入已有账本——任何工序 save() 都在历史之上累加。
起因是真实事故：e15 空批次（embedded 基线在、无待译）没有显式 merge 就 save()，
把 45.39 元累计账本覆写成空账。修复后 E4/E6 的显式 `merge_from` 全部废除（防双计），
账本损坏时宁重开不炸工序（计量非关键路径）。

### 4.5 llm.py——GLM 客户端

统一 coding 端点（`https://open.bigmodel.cn/api/coding/paas/v4`）；仅 429 限频按
Retry-After 指数退避重试，其余 HTTP 异常立即上抛（fail-fast）；全局读超时 360s
（glm-5.3 思考模式实测校准），E4 的 P1 merge 单点放宽 600s（经 client 透传，
未传不覆盖全局默认）。Key 从仓库根 `.env` 读（BYOK），缺 key fail-fast，
**禁止假 key 伪装验收**。

### 4.6 estimation.py / naming.py / logging_util.py

- `estimation.estimate_tokens`：与 pet 同口径的 token 估算（CJK 1 字=1 token、
  其余 len//4），用于 P4 预算收敛与出厂检查 prompt_budget。
- `naming.dataset_list_name`：dataset 主 list 文件名 = `{package_id}.list`，
  V1 写 / pack 查同源（消除双硬编码漂移）。
- `logging_util`：全链路日志（见 §9.3）。同进程恰好一个 `_miyako_path` 标记的
  文件 handler：同路径 setup 幂等、异路径替换、未 setup 环境 INFO 静默（测试零污染）。

### 4.7 interface.yaml——产消对账正本

每个产物字段登记 `{producer, consumer, status}`（live/reserved）。
"消费清单 = 拉取队列非上限"（D16）：字段可以超前于 pet 现行消费面（标 reserved），
但不允许"生产了没人要还不知道"的幽灵字段。

## 5. upstream 工序——从游戏文件到冻结事实源

### 5.1 E0 输入验证（e0_input_check）

**职责**：开线前体检。三探测项——①语言判定（假名/(假名+汉字) 占比，采样上限 50 文件
/10MB）；②汉化补丁扫描（resx 模式 + 有效条目计数）；③多语言台本目录探测与逐 voice_id
对齐率。**锁定校验**：profile 的 `bilingual_source` 非 auto 即锁定态，E0 只做
"探测结论 vs 锁定值"一致性校验，不一致 fail-fast（绝不回填、绝不改写 profile——L-0.2）。
embedded 模式下 alignment < 0.90 禁止继续（错位会污染 verbal_tics 成对统计）。
产出 `work/input_profile.json` → 报告页①常驻显示。

### 5.2 E1.5 翻译（e15_translate）——降级补缺角色

**职责**：translate 路径的机翻工序（上下文窗口 = 前后各 2 句）。2026-09-11 embedded
翻案后降级为"补缺角色"：只翻官方汉化未覆盖的 voice；**embedded 锁定且无 E1 基线时
禁止全量机翻**（fail-safe 直接跳过）。实现要点：
- **上下文窗口按对象身份映射**（`{id(e): k}`）——todo 是过滤子集，enumerate(todo) 的
  下标去切全量 entries 会送错上下文（2026-09-18 修复的实测 bug，CI 回归锁定）；
- 单条失败重试 2 次后进 `translate_review.json` 待校对清单，**不中断批次**（§4.1）；
- L6：translations.json 已译条目不重烧 API 钱；
- 空批次（无 todo）也会走 meter.save()——这正是 CostMeter 自动载账修复所针对的路径。

### 5.3 E1 语义提取（e1_semantic）——冻结链的心脏

**职责**：kirikiri 台本 json → `voice_map.json`（单一事实源）。
实现链条：`extractors/base.iter_scn_files`（按 profile 模式扫台本）→
`kirikiri_9nine.Kirikiri9nineExtractor`（按 extract_rules 字段映射抽语义条目）→
**Steam 官方汉化合并**（三语内嵌节点取繁中，OpenCC tw2s 确定性转简体，origin=localized）
→ 机翻补缺（仅官方未覆盖的 voice，origin=translated）→ schema 校验 fail-fast（违例逐条指出）
→ **冻结落盘**（indent=1 + CRLF 行尾，与手工雏形冻结件逐字节一致）→ sha256 上链。
产出 meta：`{sha256, entries: 2103, unique_voices: 2098, sprite_coverage: 0.954, missing: 0}`。
**纪律**：机翻（translated）禁入 P1/P2/P4 消费面（E4 池执法）；专名一律保留原文写法。
黄金值文件 `tests/local/golden/9nine_ep1.json` 断言 2103/0.954——数值漂移即回归，
禁止改 golden 讨好测试。

### 5.4 E2 立绘验收器（e2_sprites）——v2 转型

**职责**（2026-09-13 裁决后）：**不自产 manifest**（单一生产者=pet 侧
`tools/compose_all_sprites.py`），只做契约验收——①emotion_set 与 9 元闭集互锁、
②sprites 查表键 ⊆ 闭集、③闭集三元组 PNG 存在性（A=stand 缺 sad、B=right 缺 sleepy、
C=left 全覆盖、D=back 仅 normal 的原料层不变式）、④default 别名/dormant 在位、
⑤voice_map 需求模拟（fallback 链走通，demand exact=1.0）。
生产源解析：profile `sprites.compose_dir` 覆盖，缺省 = 材料库
`<raw_root>/../miyako_life材料库/fgimage/sprites_pkg`（Y11：缺失 fail-fast——当前归档位
待用户落盘，过渡期用 override profile 指向 pet 包内 sprites）。产出
`work/sprites_manifest.json`（pet manifest **原样直通**，pack 装配源）+ `sprites_meta.json`。

## 6. persona 工序——从台词到灵魂

### 6.1 E3 表达 DNA 统计（e3_dna_stats）——零 LLM 的确定性层

**职责**：全语料的硬统计 + Y4 词表机制。**统计归脚本铁律的本营**。

- 语料加载：ogg 存在性过滤、voice 子目录取 extract_rules（防越界 is_relative_to 检查）；
  中文侧统计以 localized 官方汉化为准（translated 禁入 P 层池的执法在 E4 池纪律）。
- **第一人称统计**：表记变体归一（わたし/あたし→私），EP1 锚点 私 211 / うち 16。
- **口癖后缀**：句尾后缀频次（EP1 top かな 1.4%，低于 2% 入选阈值 → verbal_tics 恒空表）。
- **verbal_tics 成对产出**：ja 侧达标（≥2%）配中文等价后缀（SUFFIX_EQUIV_ZH 映射表），
  `zh` 产 **string**（多等价 "/" 连接；无等价映射不产条目——2026-09-19 修复：
  原实现落 list 且允许空等价，EP2+ 达标即卡死出厂 schema）；成对概率合计 ≤0.6（§0.4 硬帽）。
- **句式指纹**：丁寧語率/转折率/平均句长/疑问率（中日成对、双落盘、黄金值断言）。
- **glossary 写法归一**：全角/半角高频 token 拉回语料一致形（TTS 对齐用）。
- **Y4 词表机制**：候选提取（称呼后缀/地名后缀/片假名长串/汉字 n-gram）→
  **三信号打分**（章节集中度=1−命中章节数/总数、紧张词共现率、极端 face 率，取均值）
  → 候选落 `wordlist_candidates.json` → 报告页人工勾选 → profile blocklist。
  **自证隔离**：E4 不得生成自己的输入过滤器。
- 双落盘：`e3_stats.json`（统计）+ `tts_config.yaml`（统计段，write_scopes persona 身份）。

### 6.2 E4 五层提炼（e4_persona）——全产线价值核心

**职责**：LLM 归纳五层人格并装配成卡。induce 槽 = glm-5.3（质量优先）。

**池纪律三连（全部脚本执法、条件人工裁定入 profile——自证隔离）**：
①origin==translated 禁入；②daily_corpus_blocklist 命中台词整句剔除
（`apply_daily_filter`，空表恒等——2026-09-19 翻案后 5 词，实测剔 4/2049 句）；
③persona.exclude_chapters 演出章排除（a15 无对话句，53 条不入 P 层池）。

**样本组与缓存**：36 组 = P1（9 情绪 × 2 弧线段，per_emotion 11 条）+ P2（9 × 10 条）+
P3（head/mid/tail 三分区各 10 条，弧线两端保底）+ P4（9 情绪 × 10 条，行为条件句优先）
+ P5 overview。**缓存指纹 = 组名 + 样本集内容 sha256**（2026-09-18 修复：原只哈希 voice id
集，同 id 换内容不失效——违背 L1；现哈希提示词消费全字段 voice/emotion/chapter/text_zh/text）。
旧格式缓存按 plan v2.3 既定语义视为 stale（宁严勿松）。

**逐组执行 `_run_group`**：初跑 → 产出严格 JSON → 质量门（缺字段/引用不存在的样本 id/
**P3 逐字引用门**）→ 不合格带原因 refine 重试（≤2 轮）→ 仍不合格 failed=true 转人工
（宁严勿松，不静默无限循环）。**P3 逐字引用门（p3_quotes_verbatim）**：每条 zh 与组内
样本 text_zh 空白归一化后必须全等——LLM 漂移引用（截断/拼接/改写）会使语气示例对不回
语料（arc_ends 尾锚断、few-shot 失真的实证对策）；prompt p3 v1.1.0 同步威慑注记。

**P1 合并**：18 个 p1 分片 → 一次 merge 调用产出 persona_prose（≥200 字）+ description +
traits/values/core_tensions + evidence。合并缓存键 = 分片内容 hash + merge 提示词版本 hash
（prompt 升版自动失效）。单点超时 600s（全局 360s 不够时只放宽此处）。

**兜底扫描 fallback_scan**：转人工前的辅助材料（头尾加权 + 关键词条选，≤20 万字符，
计入成本面板）——产出不得直接进卡。

**卡装配 assemble_card**（纯脚本，零 LLM）：
- 身份字段读 profile（display_name/name/calls_you——2026-09-13 profile 化，硬编码废除）；
- **tone 选择**：p3 池 2 条/情绪（tone_min_chars=10 过滤 → skipped 暂扣 → 宁短勿空回填）
  → 确定性 fallback（records 原句，天然逐字）→ 全局 leftover 补齐 → **尾段保证**
  （tail 三分区零覆盖时按 voice 序替换"最厚情绪"第 2 槽，保 9×2 结构）；
- **P4 收敛（D16 密化）**：排序键 = 证据形态（explicit 优先）→ 跨组复现数 → 稳定序，
  按 prompt_budget_tokens=2000 预算填充，超出留 e4_persona.json 审计层（容器端截断不算
  合规降级）；
- P1 密度安全帽（traits≤8/values≤6，merge prompt 硬帽的脚本侧兜底）；
- schema 校验（报错带字段路径）→ 落 `character_card.yaml` → **每炼必存**
  （快照按内容哈希归档 `work/card_archive/`，同版本不重复）。

**E6 喂养关系**：E6 消费当前卡做验证；卡一变，E6 必须重跑，盲测决策按 Y5 自动 stale。

### 6.3 E6 自动验证（e6_validate）——护栏而非质量证明

**定位（Y8）**：E6 是回归护栏；扮演质量的最终裁决是人工盲测。
judge 槽 = glm-5.3-flash（与 induce 异型号防自证）。

四段验证：
1. **20 例已知问题测试**：induce 生成回应 → 确定性信号（[e:情绪] 标签 ∈ 闭集、
   dialog_v1 单行合规）→ judge 独立打分（评分锚点 0~100，60 及格）→ 方向关键词
   （must/forbid）降级为报告信号不作为门槛（词法匹配无法区分否定/转述——t01 教训）；
2. **反模式断言**：P5 禁忌出现即违规聚合；
3. **证据回查**：引用 → 原文相似度（SequenceMatcher 比率与最长匹配覆盖率取 max；
   阈值 0.30），低于阈值进"待审"区不直接 fail；inferred 降权；
4. **覆盖面断言**：四维（自我认知/表达风格/情绪与决策模式/行为规则）各 ≥N 条
   explicit（N=profile coverage_min_explicit）。

**fail-closed 纪律**：judge 调用失败该例计未通过；生成空响应计未通过（2026-09-19 修复
IndexError）；汇总 verdict 写 `e6_report.json`。当前基线 18~20/20（历史 14/20）。

## 8. pack 工序——报告页、决策账本与出厂闸门

### 8.1 report_builder——报告页 + 决策账本（L4.1/L4.2）

**报告页**（`work/report.html`）：本地 HTML，九区块（输入档案/成本面板/人格区+

### 8.2 packager——出包装配

**流程**：装配到 staging → `run_factory_check`（fail-closed）→ 旧包时间戳备份 →
staging 替换 final → **完整 card 镜像**同步 `card/{pkg_id}`（仅完整包写镜像，
voice-less 诊断包不覆盖——9-16 镜像污染事故的对策）。

**装配清单**（write_scopes：pack 物理写入，内容所有权归各工序）：
character_card ← work；tts_config ← work（--voice-less 时**删** edge_voice 键 = tier-0
形态，2026-09-16 schema 修正）；relationship ← contracts/golden_pair（EP1 直接复用）；
sprites ← E2 验收源直通（compose_dir 缺省材料库位，缺失 fail-fast）；audiofile ← V1 九桶；
reference_audio ← V2 候选+meta；tts/ ← **重训权重随卡**（2026-09-16 用户裁定）；manifest ← pack 计算。

**voice_tier 伪码（永不变更）**：`ref_audio_ready and dataset_ready → 2；elif
edge_voice 非空 → 1；else 0`。dataset 就绪检查走 dataset_list_name(profile) 同源。

**权重选取 latest_weight**：只认**正典训练产出名**（全名匹配 `miyako_e{e}_s{s}.pth` /
`miyako-e{e}.ckpt`），按 (epoch, steps) 确定性取最大；人工备份变体名跳过并警告
（2026-09-18/19 两轮修复：原实现同 epoch 平局取决于目录枚举序——盘面 SoVITS 同存
原型 e8_s3904 与重训 e8_s3928；且变体名 `-fix` 会按名字序被误选）。

**card_digest_of——双口径定案**：manifest 的 `card_digest` = **LF 归一化文本口径**
（read_text universal-newlines 把 CRLF→LF 再哈希；同内容跨平台同值——盲测锚 dde7cd7f
即此口径）；decisions Y5 绑定的是**文件字节口径**（Windows 下不同值）。两口径各司其职、
CI 锁定其关系（CRLF/LF 同 digest、与字节口径必异）。

## 12. 质量与安全闸门

三层闸门从内到外：

1. **工序级 fail-fast**：E0 探测不符/E1 schema 违例/E2 归档缺失/E3 越界——立即停车，
   防上游错污染全链（§4.1 失败矩阵）；
2. **LLM 级 fail-closed**：judge 失败计未通过、逐字门不合格转人工、refine ≤2 不静默循环；
3. **出厂级 fail-closed**：13 项检查（§8.3）任一不过不出包。

安全红线（有 CI 执法）：游戏资产不入 git；角色包禁二次分发；API Key BYOK 入 .env；
音频零外发（训练走本地/自有 share 包）；云端 LLM 仅见抽样文本（evid 引用形态）。
